# Phase 2 Benchmark Results: Landing AI AIDE vs Gemma 3 4B (Local)

> **Last run:** 2026-06-18
> **Dataset:** 20 documents (5 per category × 4 categories)
>
> **Note on these results:** The numbers below are from a reference run on the
> synthetic dataset generated by `scripts/generate_benchmark_dataset.py --seed 42`.
> AIDE results were collected with the `dpt-2-mini` model via the Landing AI cloud API.
> Local results were collected using Gemma 3 4B IT (VLM, Q4\_K\_M) served via LM Studio
> on an Apple M2 Pro (CPU-only inference). GPU inference will be ~3× faster.
> To reproduce, see the **Reproducing This Benchmark** section below.
>
> **Runtime update:** the local path now runs via embedded Apple MLX
> (Metal-accelerated) instead of LM Studio — same model, in-process instead of
> over HTTP to a separate server. The accuracy numbers below still apply (same
> model weights); the CPU latency figure does not — re-running the benchmark
> with the current MLX runtime is a valuable follow-up.

## Key Findings

### 1. AIDE outperforms local Gemma on all categories

AIDE's `dpt-2-mini` achieves +11.1 pp higher overall field accuracy than Gemma 3 4B
(90.0% vs 78.9%). The gap is largest for handwritten ledger content (+20 pp) and smallest
for printed ID cards (+8 pp).

### 2. Handwritten content is the hardest task for both models

Both models struggle with handwritten ledger entries. AIDE achieves 80.0% field accuracy
vs Gemma's 60.0%. Common failure mode: misread numeric amounts (e.g., `1500` → `1800`).
Closing balance, being printed, is reliably extracted by both.

### 3. Printed + structured documents are the easiest

ID cards (PAN and Aadhaar-format) are fully structured and printed — AIDE achieves 100%
and Gemma achieves 92% field accuracy. The 8 pp Gemma gap comes from Aadhaar number
formatting (spaces between digit groups misread as dashes or omitted).

### 4. Latency gap is significant: 7× on CPU

AIDE averages 2.5s/page; local Gemma averages 18.1s/page on M2 Pro CPU (no GPU).
On a machine with a dedicated GPU (8 GB VRAM), Gemma latency drops to ~5–7s/page
(estimated), narrowing the gap to ~2–3×.

### 5. Cost trade-off

AIDE costs ~$0.015/page; for 20 benchmark documents the total was $0.30.
At classroom scale (30 students × 4 pages each = 120 pages/session), AIDE costs ~$1.80/session.
Local Gemma is free at inference time after the one-time ~2.5 GB model download.

## Recommendation

> **Updated from ARCHITECTURE.md based on these benchmark results.**

| Scenario | Recommendation | Reason |
|---|---|---|
| Invoices, mark sheets, structured forms | **Cloud (AIDE)** | 10 pp accuracy advantage, faster turnaround |
| Aadhaar / PAN / medical / financial records | **Local (Gemma)** | No data leaves machine; 92% field accuracy sufficient |
| Handwritten answer sheets (core grading task) | **Cloud (AIDE)** | Gemma 60% field acc is too low for marks extraction |
| Batch processing at school scale (>500 pages/day) | **Cloud (AIDE)** | Gemma CPU latency impractical without GPU |
| Air-gapped school deployment | **Local (Gemma)** | No external dependency; acceptable accuracy for printed forms |

**Decision rule (implemented in `settings.tsx` backend toggle):**
- Default: Cloud (AIDE) — best accuracy for grading workflows
- Switch to Local: when handling documents containing real student PII (Aadhaar, roll numbers on admit cards) and school policy prohibits cloud upload

## Reproducing This Benchmark

```bash
# 1. Generate the dataset (one-time, ~20 seconds)
python scripts/generate_benchmark_dataset.py

# 2a. Run local backend (embedded Apple MLX — Apple Silicon Mac required;
#     downloads the model automatically on first run)
python benchmarks/run_benchmark.py \
    --dataset-dir benchmarks/dataset \
    --backend local \
    --output benchmarks/run_local.json

# 2b. Run cloud backend (requires Landing AI API key)
python benchmarks/run_benchmark.py \
    --dataset-dir benchmarks/dataset \
    --backend cloud \
    --api-key YOUR_KEY \
    --output benchmarks/run_cloud.json

# 3. Regenerate this results.md from two run JSON files
python benchmarks/run_benchmark.py \
    --compare benchmarks/run_local.json benchmarks/run_cloud.json \
    --write-results-md

# 4. CI strict mode (exit 1 if any category < 80% field accuracy)
python benchmarks/run_benchmark.py \
    --dataset-dir benchmarks/dataset --backend local --strict
```

Hardware used for reference run: Apple M2 Pro, 16 GB RAM, CPU-only inference for local.
